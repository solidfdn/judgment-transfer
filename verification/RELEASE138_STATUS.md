# Release 1.0.38 — stable execution of approved conditions

Category: execution-policy revision within the owner's requested stable automation product. Not a transport-only patch. The owner approved deterministic execution for exact conditions in the design discussion and asked to eliminate recurrent failures without extending waits.

The saved after-run has one success, one technical failure and two untouched tasks. Both failed model attempts produced no chunks in 60 seconds. The upstream cause is undetermined. This release does not claim that Gemini availability has recovered.

C_JT_RULES now executes the approved declarative workflow using the existing three-valued evaluator/executor. Positive matched actions and explicit holds apply directly. Incomplete, conflicting or unmatched conditions use the declared default hold without inventing a matching rule. Missing approval/evidence is a technical error. No model failure is converted into a business result. All current source versions and rule references are validated before execution. Lease, expiry, version CAS, receipts and scoring remain in place. Gemini is retained for document/workflow review, questions and guidance proposals. A/B remain explicit model paths. No model, SDK, timeout, price, quota or budget change.

New execution provenance: APPROVED_RULE_ENGINE_V1 on each run; APPROVED_RULE or APPROVED_RULE_DEFAULT on each task; RULE_ENGINE trace with exact inputs, approved version, source hashes and no model attempts. English UI and guided demo state the method. No label or fixture dependency in the engine.

A new explicit approved_version option selects only stored, named human-approved workflow versions in the owned workspace. It cannot inject arbitrary rules. Historical version replay uses only that domain's evidence, with no future human explanation supplied to v0. Evaluation holdout still requires the frozen current version and code. Old unfinished runs cannot continue under new code.

This is a replay of already-approved versions, not fresh Gemini decisions. No source reading, question/proposal regeneration, reapproval or allowance POST.
